
讲解 User Rules 和 Project Rules 准备的提示词

User Rules 规则

- 我使用Java17或者更高版本
- 遵循标准的Java命名规范：类名用PascalCase，方法名用camelCase，变量名用camelCase，常量名全部大写下划线。
- 所有 public 方法必须包含完整的 Javadoc 注释，包括 @param、@return、@throws 等。
- 优先使用不可变对象和final关键字（如 final class 、 final fields）。
- 避免使用Lombok：显式编写getter、setter、构造函数等，避免使用Lombok的注解。
- 异常处理应具体，避免捕获通用Exception，优先抛出或记录有意义的异常。
- 使用SLF4J进行日志记录，避免直接使用System.out.println()。
- 依赖注入使用 Spring Framework 或其他依赖注入框架（如 Guice、Dagger 等）。
- 单元测试使用 JUnit5 + Mockito 进行单元测试，确保代码质量和功能正确性，每个业务类都有对应的测试类。


Project Rules 规则

- 本项目是一个基于 Spring Boot3.2 的Restful API 项目，使用 Java17 作为开发语言。
- 包结构遵循 Maven 标准目录结构，主要包括：
  - `src/main/java`：存放 Java 源文件，按照功能模块组织包结构。
  - `src/main/resources`：存放配置文件、静态资源等。
  - `src/test/java`：存放测试用的 Java 源文件，按照功能模块组织包结构。
  - `src/test/resources`：存放测试用的配置文件、静态资源等。
例如：
- `com.example.demo.controller`：存放控制器类，处理 HTTP 请求。
- `com.example.demo.service`：存放服务类，实现业务逻辑。
- `com.example.demo.repository`：存放数据访问层类，与数据库交互。
- `com.example.demo.model`：存放实体类，映射数据库表结构。
- `com.example.demo.config`：存放配置类，配置 Spring Boot 应用。
- `com.example.demo.test`：存放测试类，使用 JUnit5 + Mockito 进行单元测试。
- Controller层只负责HTTP请求的处理，不包含业务逻辑。
- Service层负责业务逻辑的实现，与Controller层解耦。
- Repository层负责数据访问，与Service层解耦。
- Model层负责实体类的定义，映射数据库表结构。
- Config层负责配置类的定义，配置 Spring Boot 应用。
- Test层负责测试类的定义，使用 JUnit5 + Mockito 进行单元测试。
- 所有请求/响应使用DTO（Data Transfer Object）进行数据传输，避免直接使用实体类。
- 数据库使用MySQL作为数据库，使用JPA（Java Persistence API）进行数据访问。
- 数据库表结构使用MySQL Workbench进行设计和管理。
- 数据库连接配置在`application.properties`文件中，包括数据库URL、用户名、密码等。
- 全局异常处理通过`@ControllerAdvice`和`@ExceptionHandler`注解实现，统一处理应用程序中的异常。
- 使用Jakarta Validation（Hibernate Validator）进行请求参数的校验，确保数据的合法性。
- 配置文件使用 application.yml 进行配置，敏感信息通过环境变量注入。
- 构建工具使用 Maven 进行项目构建，确保依赖管理和项目编译。
